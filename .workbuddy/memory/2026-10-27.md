## 修复：归档页「份数」虚高（11 份 → 6 份）
- 现象：用户反馈 GitHub 上显示生成 11 份分析日报。
- 根因：`src/sources.py` 的 `load_sources` 汇总窗口 3 天，`items` 保留了同一任务多天的文件
  （chatgpt/gemini/grok/national/xiangcong 各 10-26 与 10-27 两份，共 10 个 item）。
  而 `build_tasks_index` 的 `n_all = 1 + len(items)`、报告多源卡片墙、归档 `task_prices`
  均直接用原始 `items` 长度计数 → 每个任务按天重复，同一任务出现两次且价格不同。
  另：`tasks/<slug>.html` 循环写入时后被写入的旧数据会覆盖新数据（items 按日期倒序，
  最后一次写的是最早日期），任务页可能展示旧一期。
- 修复：在 `sources.load_sources` 内按任务 slug 去重（`_slug_from_filename`，口径与
  `report._task_slug` 一致），每个任务仅保留窗口内最新一期；保留「当天漏跑可回退前几天」的回退能力。
  `files_scanned` 仍统计扫描文件总数，`task_count` 保持真实任务数。
- 结果：index.html / tasks/index.html 均显示 6 份（本日报+5任务），archive.json task_prices 5 条不重复，
  报价统计由含重复的 283 条变为当期的 200 条。commit `f209a48`。

## 经验（ Git 操作）
- 本仓库 CI 常在本地推送前抢先提交，`git pull -X ours` 会因分支分叉失败，直接走
  `git fetch && git rebase origin/main` 更稳。
- rebase 解冲突遍历文件列表时必须用 `git -c core.quotepath=false diff --name-only --diff-filter=U -z`
  配合 `while IFS= read -r -d ''`，否则中文文件名会被转义成八进制带引号字符串，
  导致 `git checkout --theirs` 报 pathspec did not match。
